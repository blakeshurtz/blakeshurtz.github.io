tidymodels and Kaggle

Building a repeatable machine-learning workflow in R with tidymodels and Kaggle.

Kaggle is a useful place to practice on a real problem. The data is already collected, the objective is clear and the leaderboard gives you immediate feedback. It is tempting to keep changing the model until the score moves up. That can work, but it does not tell you whether the model will perform well on new data.

For that reason, I use tidymodels to keep the workflow organized. The same steps used to prepare the training data are saved and applied to the test data. Resampling happens locally. Kaggle is the final check, not the validation strategy.

Data Preparation

A recipe keeps the preprocessing next to the model. In this example, missing numeric values are imputed, categorical predictors are converted to dummy variables and predictors with no variation are removed.

library(tidymodels)

set.seed(123)
folds <- vfold_cv(train_data, v = 10, strata = outcome)

kaggle_recipe <- recipe(outcome ~ ., data = train_data) |>
  step_impute_median(all_numeric_predictors()) |>
  step_unknown(all_nominal_predictors()) |>
  step_dummy(all_nominal_predictors()) |>
  step_zv(all_predictors())

The recipe also prevents a common Kaggle problem: making one set of changes to the training data and a slightly different set of changes to the submission data.

Model Tuning

Tidymodels provides consistent syntax across model engines. I can start with a random forest, define the parameters I want to tune and combine everything into one workflow.

rf_model <- rand_forest(
  mtry = tune(),
  min_n = tune(),
  trees = 1000
) |>
  set_mode("classification") |>
  set_engine("ranger")

rf_workflow <- workflow() |>
  add_recipe(kaggle_recipe) |>
  add_model(rf_model)

rf_results <- rf_workflow |>
  tune_grid(
    resamples = folds,
    grid = 20,
    metrics = metric_set(roc_auc, accuracy)
  )

The leaderboard score is easy to see. The more important result is the distribution of scores across the ten folds. If a model performs well on average and does not fall apart on a few folds, I have more confidence that the improvement is real.

Kaggle Submission

Once the model is selected, I finalize the workflow and train it on the full training set. Predictions are then written in the exact format expected by Kaggle.

final_workflow <- rf_workflow |>
  finalize_workflow(select_best(rf_results, metric = "roc_auc"))

final_fit <- final_workflow |>
  fit(data = train_data)

submission <- predict(final_fit, kaggle_test, type = "prob") |>
  bind_cols(kaggle_test |> select(id)) |>
  transmute(id, outcome = .pred_yes)

write_csv(submission, "submission.csv")

Then, submit the file and see where it lands. If the public score and the resampling results tell different stories, I trust the resampling results first. A public leaderboard is still a sample, and repeatedly submitting against it is another way to overfit.

What I like about this workflow is that it scales beyond a competition. The recipe, model specification and tuning results can be saved, reviewed and reused. Kaggle makes the exercise fun. Tidymodels makes the result reproducible.
